# Farm World V0.9 — Staging integration handoff
Status: typed RPC adapter, read-only server snapshot UI, and boundary unit tests implemented. **No Supabase project has been connected or migrations executed. No live online gameplay.**

## Delivered
- `lib/farm-online.ts`: authenticated snapshot reader for player_farms/farm_state/farm_plots; typed command adapter for V0.8 `farm_apply_command`, request UUID supplied by caller, validation of inputs and results.
- `app/account-panel.tsx`: when V0.7 Supabase is configured and authenticated, user can view server coins, harvest count, revision and planted plot count. Never overwrites offline state.
- `tests/farm-online.test.ts`: command validation and response boundary checks.
- Existing local save `farm-world-v01b-save` and progression `farm-world-v04-progression` are untouched. Offline gameplay remains available.

## Strict release gates
1. Configure NEW Supabase staging, apply migrations 0002 then 0003, provision two users through trusted admin only.
2. Confirm two-user RLS isolation, expired session, unauthorized writes, and cross-owner read denial.
3. Run RPC concurrency/idempotency/replay tests with stable UUIDs and server clock. Reusing a UUID with a different payload must fail.
4. Test client read-only snapshot on iOS and Android, including reconnect/logout. Compare online vs offline without merging.
5. Build and deploy Pages successfully, inspect real CI jobs and browser console.
6. Review SECURITY DEFINER SQL privileges, rate limiting, audit/retention, backups and recovery.
7. Before enabling real online gameplay, add authoritative inventory, selling, XP, quests, client command queue with persisted request IDs, reconciliation, and verified migration consent. V0.8 RPC harvest currently awards coins immediately; offline V0.4 harvest adds inventory. **Do not mix these economies or present the RPC as feature-parity gameplay.**

## Rollback
No automatic migration of local saves. Disable Supabase environment variables in Pages and redeploy to restore offline-only mode. Do not delete production data. All staging schema changes require manual review.

## Explicit limitations
No live database tests, two-account E2E, cloud migration, anti-abuse controls, or active online mutations are claimed. The command adapter exists for controlled future integration but the UI deliberately does not invoke it.
