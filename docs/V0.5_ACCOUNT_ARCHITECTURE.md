# Farm World V0.5 — Account and authorization foundation
Status: design + pure authorization contract only; NOT a production login implementation.

## Architecture
- GitHub Pages: static offline guest game, localStorage V1 farm + V2 progression; never stores real credentials or tokens.
- Future backend: independent HTTPS API service (not GitHub Pages) with verified identity provider, secure HttpOnly/Secure/SameSite session cookie, CSRF defenses, rate limiting and audit logs.
- Database: users(id), farms(id, owner_id), farm_state(farm_id, state_version, state_json), action_requests(farm_id, request_id, result_json, created_at). Unique(farm_id,request_id).
- A verified session resolves userId server-side; never trust userId/ownerId/farmId from client as authority. Every query/mutation scopes by owner_id + farm_id.
- Authorization: deny by default; 401 for unauthenticated, 403 for nonowner. Do not expose other users' data in error responses.
- Game economy: all planting, harvesting, sales, XP and quest rewards are server-authoritative using server time and atomic database transactions. Idempotent command requestId prevents duplicate rewards.
- Save import: user explicitly opts in; validate old V1 farm and V2 progression; preview, create server-side backup, migrate once in transaction. Never overwrite online state silently.
- Security: hashed passwords via maintained identity provider (never raw SHA-256), no client secrets, environment separation, no production DB access during V0.5.
- Privacy: minimum account data, deletion/export policies before public online launch.

## Acceptance gates
1. Static offline gameplay remains functional and existing saves remain untouched.
2. Pure authorization tests cover anonymous, expired, cross-owner, allowed owner and malformed commands.
3. CI: typecheck, lint, unit tests, build and Pages deployment PASS.
4. Online login, real farm isolation and concurrency tests are **NOT** accepted until a real backend exists (V0.6).
5. Physical iOS Safari and Android Chrome smoke tests remain manual.

## V0.6 integration checklist
Choose backend hosting + managed PostgreSQL + identity provider; create additive migrations; configure separate test environment; implement session verification and ownership checks at every endpoint; transactional/idempotent commands; concurrent user isolation tests; rollback and backup plan; CI + deployment gates.
